## 1. Что такое скрипт (на пальцах)

Представьте два прибора.

**Первый — магнитофон.** Вы нажали «Запись», поработали мышкой, нажали «Стоп». Теперь он повторяет ровно то же самое: те же движения, те же клики, с теми же задержками. Всегда одинаково. Это **обычный макрос**, и он у вас уже работает без всяких скриптов.

Проблема у магнитофона одна: он **слепой**. Он не смотрит на экран. Если игра сегодня грузится на три секунды дольше, магнитофон всё равно кликнет по расписанию — в пустоту. Весь прогон насмарку.

**Второй прибор — список дел с условиями.** Примерно такой:

> 1. Жди, пока на экране появится кнопка «Забрать».
> 2. Нажми её.
> 3. Повтори кусок записи с 0-го по 240-е действие.
> 4. Посмотри, сколько у меня гемов.
> 5. Если меньше 500 — вернись к пункту 1.

Вот это и есть **скрипт**. Он умеет **ждать**, **проверять** и **повторять нужное число раз**. И при этом внутри себя он по-прежнему может проигрывать куски вашей записи — так что заново кликать всё руками не придётся.

> **Главное:** скрипт не заменяет запись. Скрипт **управляет** записью. Вы записываете скучную часть один раз, а сверху навешиваете «жди вот это» и «повтори, пока не наберётся столько-то».

## 2. А мне это вообще нужно?

Честный ответ: **чаще всего — нет**. Скрипт нужен, только когда слепого повтора не хватает.

| Ваша ситуация | Нужен ли скрипт |
|---|---|
| «Мне надо, чтобы одно и то же нажималось 500 раз» | ❌ Нет. Просто запись + «Циклическое воспроизведение» |
| «Мне надо, чтобы оно работало 3 часа и потом выключило ПК» | ❌ Нет. Это раздел **⏱ Лимит времени** в главном окне |
| «Мне надо остановиться, когда полоска покраснеет» | ❌ Нет. Это раздел **🎯 Условие по пикселю** |
| «Кнопка появляется не сразу, а когда как» | ✅ **Да.** Шаг `Ждать` |
| «Кнопка каждый раз в разном месте» | ✅ **Да.** Шаг `Клик по картинке` |
| «Надо повторять, пока не наберётся 500 гемов» | ✅ **Да.** `Пока` + `Прочитать число` |
| «Если выпало окно ошибки — закрой его, иначе продолжай» | ✅ **Да.** `Если` / `Иначе` |
| «Надо сделать ровно 20 кругов и запустить другую программу» | ✅ **Да.** `Пока` + переменная + `Запустить` |

Если вы попали в верхние три строки — закройте это руководство, вам оно не нужно. Всё уже есть галочками в главном окне.

## 3. Первый скрипт за пять минут

Сделаем самое простое: **макрос, который сначала ждёт 2 секунды, потом проигрывает вашу запись, и так по кругу.**

Бесполезно? Да. Но вы увидите, где вообще всё находится, и дальше будет легко.

### Шаг 0. Запишите хоть что-нибудь

Нажмите `F6`, покликайте мышкой пару секунд, нажмите `F6` ещё раз. В окне должно появиться что-то вроде **📦 Событий: 47**.

Без записи скрипт тоже работает, но редактор просто не откроется — ему нечего показывать.

### Шаг 1. Откройте редактор

В главном окне разверните раздел **✂ Редактор** и нажмите **✂ Открыть редактор**.

Откроется отдельное окно. Вверху три вкладки:

```
📦 Событий: 47   ⏳ Длительность: 3.2 с  |  [ Рассказ ] [ Сырые события ] [ Скрипт ]
```

### Шаг 2. Перейдите на вкладку «Скрипт»

Нажмите **Скрипт**. Увидите надпись:

> Скрипта нет — макрос просто повторяет запись

Это нормально. Скрипта действительно ещё нет.

### Шаг 3. Добавьте первый шаг

Внизу есть выпадающий список и кнопка **Добавить**.

1. Выберите в списке **Пауза**.
2. Нажмите **Добавить**.

В списке появилась строка:

```
  0 Пауза 1000 ms
```

Ниже, в инспекторе, есть поле **Вставить паузу (мс)**. Поставьте туда `2000` — это 2 секунды.

```
  0 Пауза 2000 ms
```

### Шаг 4. Добавьте второй шаг

1. Выберите в списке **Воспроизвести события**.
2. Нажмите **Добавить**.

```
  0 Пауза 2000 ms
  1 Воспроизвести события 0…46  (47/47)
```

Обратите внимание: программа сама подставила **всю запись целиком** — с нулевого события по последнее. Это то, что нужно в 90 % случаев.

### Шаг 5. Запустите

Закройте окно редактора (или оставьте, не важно) и нажмите **▶ Воспроизвести** — или клавишу `F7`.

Макрос подождёт две секунды и проиграет запись. Если в главном окне включено **Циклическое воспроизведение**, он будет делать это по кругу.

**Всё. Вы написали скрипт.** Дальше — только новые виды шагов.

> 💡 Если что-то пошло не так — нажмите `F9` (аварийный стоп). Он останавливает всё и всегда.

## 4. Как читать окно скрипта

Строка в списке выглядит так:

```
  3     Клик по картинке: claim_button ≥ 0.85
  ↑ ↑   ↑
  │ │   └── что делает шаг
  │ └────── отступ = вложенность (шаг внутри «Если» или «Пока»)
  └──────── номер шага
```

Что означают цвета и оформление:

| Как выглядит | Что это значит |
|---|---|
| Обычный текст | Нормальный включённый шаг |
| ~~Зачёркнутый серый~~ | Шаг **выключен** — движок его пропустит. Снимите/поставьте галочку **вкл** |
| 🟠 Оранжевый текст | Шаг **никогда не выполнится** — он стоит после `Закрыть программу` |
| 🟠 `⚠ Незакрытые блоки: …` | Ошибка: где-то не хватает `Конец если` или `Конец пока`. **Такой скрипт не запустится вообще** |

Кнопки под списком:

| Кнопка | Что делает |
|---|---|
| Список + **Добавить** | Вставляет новый шаг **сразу после выделенного** |
| **Шаг из выделения** | Создаёт `Воспроизвести события` из диапазона `с`/`по`, заданного на вкладке **Сырые события** |
| **▲** / **▼** | Двигает выделенный шаг вверх/вниз |
| **Удалить действие** | Удаляет выделенный шаг |
| **вкл** | Временно выключает шаг, не удаляя его |

Ниже — **инспектор**: набор полей для того шага, который сейчас выделен. У `Паузы` там одно поле, у `Клика по картинке` — три, у `Если` — целый блок с выбором условия.

> ⚠️ Во время записи или воспроизведения редактор заблокирован. Сначала `F9`, потом правьте.

## 5. Четыре правила, которые надо запомнить

### Правило 1. Шаги выполняются сверху вниз

Как чтение книги. Шаг 0, потом 1, потом 2. `Если` и `Пока` могут перекинуть выполнение в другое место, но всё остальное идёт строго по порядку.

### Правило 2. Весь скрипт — это один «круг»

Настройки **Циклическое воспроизведение** и **Проигрываний: N** в главном окне повторяют **скрипт целиком**, от первого шага до последнего.

```
Проигрываний: 3   →   [весь скрипт] [весь скрипт] [весь скрипт]
```

Не путайте с шагом `Пока` — тот крутит цикл **внутри** одного круга.

### Правило 3. Если скрипта нет — работает обычный повтор

Пустой скрипт (или скрипт, где **все** шаги выключены) = обычный макрос. Ничего не сломается.

### Правило 4. Некоторые галочки главного окна в скрипте не работают

Это важно, и об этом легко забыть:

| Настройка | В скрипте |
|---|---|
| Циклическое воспроизведение / Проигрываний | ✅ Работает |
| Пауза между циклами | ✅ Работает |
| Лимит времени (остановиться через N часов) | ✅ Работает |
| Скорость (ползунок и клавиши быстрее/медленнее) | ⚠️ Влияет **только** на шаг `Воспроизвести события` |
| Привязка к окну | ⚠️ Влияет на `Воспроизвести события` и `Клик в`, но не на `Клик по картинке` |
| **Джиттер таймингов** | ❌ Не работает |
| **🎯 Условие по пикселю** (стоп по пикселю) | ❌ Не работает — используйте условие `пиксель` внутри скрипта |
| **Действие после лимита** (выключить ПК, сон…) | ❌ Не работает — скрипт просто останавливается |
| **Искать только в области / другие масштабы** | ❌ Не работает — это только для кнопки проверки в панели |

Если вам нужно «после скрипта выключить ПК» — сделайте это шагом `Запустить` с путём `shutdown` и аргументами `/s /t 60`.

| Шаг | Одной строкой |
|---|---|
| **Воспроизвести события** | Проиграть кусок записи с события N по событие M |
| **Пауза** | Просто подождать столько-то миллисекунд |
| **Ждать** | Ждать, пока условие станет правдой (или перестанет быть) |
| **Клик по картинке** | Найти картинку на экране и кликнуть по ней |
| **Клик в** | Кликнуть по точным координатам |
| **Клавиша** | Нажать или отпустить одну клавишу |
| **Присвоить** | Записать число в переменную (`=`, `+=`, `-=`, `*=`) |
| **Если** | Начало блока «если условие верно, то…» |
| **Иначе** | «…а иначе…» |
| **Конец если** | Конец блока «Если» |
| **Пока** | Начало цикла «повторяй, пока условие верно» |
| **Конец пока** | Конец цикла |
| **Прервать** | Выйти из цикла досрочно |
| **Запустить** | Открыть программу, файл, папку или ссылку |
| **Закрыть программу** | Закрыть сам Macro Recorder |
| **Заметка** | Записать текст в лог-файл (для отладки) |
| **Прочитать число** | Распознать число на экране и положить в переменную |
| **Найти картинку** | Найти картинку и доложить, где она, ничего не нажимая |
| **Прочитать текст** | Распознать область в **текстовую** переменную |
| **Взять текст** | Буфер обмена, заголовок окна, активная программа или файл → переменная |
| **Записать текст** | Переменная или текст → буфер обмена или файл |
| **Найти элемент** | Спросить у Windows про элемент интерфейса и доложить, где он |
| **Нажать элемент** | Нажать элемент интерфейса силами самого приложения |

## 7. Все шаги: подробно

### ▶ Воспроизвести события

**Поля:** `с` (номер первого события), `по` (номер последнего).

Проигрывает кусок вашей записи с исходными задержками между действиями. Это мост между «магнитофоном» и скриптом.

Как узнать нужные номера:
1. Перейдите на вкладку **Сырые события** или **Рассказ**.
2. Найдите нужное место, посмотрите номер строки слева.
3. Либо задайте поля `с` / `по` внизу и нажмите **Шаг из выделения** — номера подставятся сами.

**Особенности:**
- Новый шаг по умолчанию покрывает **всю запись** (0 … последнее событие).
- Это **единственный** шаг, на который влияет ползунок скорости и клавиши «быстрее»/«медленнее».
- Клавиша «пропустить шаг» бросает остаток куска и переходит к следующему шагу.
- Если вы потом удалите события в редакторе, номера в шаге останутся старыми. Проверьте их.

---

### ⏸ Пауза

**Поле:** `Вставить паузу (мс)` — от 0 до 3 600 000 (это час).

Просто ждёт. 1000 мс = 1 секунда.

**Особенность:** ползунок скорости **не** влияет на этот шаг. Пауза 2000 мс — это 2 секунды и при скорости 0.5×, и при 3×.

Кнопка «Стоп» реагирует во время паузы моментально: движок спит кусочками по 15 мс и постоянно проверяет, не пора ли остановиться.

---

### ⏳ Ждать

**Поля:** условие · `появится` / `исчезнет` · `Таймаут (мс)` (по умолчанию 10 000).

Самый полезный шаг во всём наборе. Останавливает скрипт до тех пор, пока что-то не случится на экране.

- **появится** — ждать, пока условие станет **верным**;
- **исчезнет** — ждать, пока условие станет **неверным** (например, пока не пропадёт экран загрузки).

Условие проверяется примерно 8 раз в секунду.

> ⚠️ **Очень важно:** когда таймаут вышел, скрипт **не останавливается и не ругается**. Он просто идёт дальше на следующий шаг, как будто всё в порядке (в лог пишется `wait timed out`).
>
> Поэтому не пишите так:
> ```
> 0  Ждать   картинка: claim  появится  (10000 мс)
> 1  Клик в  (960, 540)
> ```
> Если картинка не появилась за 10 секунд, шаг 1 всё равно кликнет. Пишите так:
> ```
> 0  Ждать           картинка: claim  появится  (10000 мс)
> 1  Если            картинка: claim ≥ 0.85
> 2      Клик по картинке: claim ≥ 0.85
> 3  Конец если
> ```

### 🖼 Клик по картинке

**Поля:** `Шаблон` (имя файла) · порог (0.30–1.00) · кнопка мыши · `по контурам` · **Область**.

Ищет картинку на экране и кликает по её **центру**.

- Шаблон — это имя PNG-файла из папки `templates/`. Пишите `claim_button` или `claim_button.png` — работает и так, и так. **Папка** с таким именем — это набор вариантов, см. [раздел 11](#11-шаблоны-картинок-как-сделать-правильно).
- Если картинка **не найдена**, шаг молча ничего не делает и скрипт идёт дальше.
- Между нажатием и отпусканием кнопки — 30 мс.
- Привязка к окну на этот шаг **не влияет**: координаты берутся прямо с экрана, потому что картинку и так нашли по факту.

**Область** — поле, от которого зависит скорость, и оно есть у каждого шага и каждого условия с картинкой:

| Область | Что просматривается | Когда брать |
|---|---|---|
| **весь экран** | все мониторы | по умолчанию и самое медленное |
| **активное окно** | то, что сейчас впереди | почти всегда верно и заметно быстрее |
| **прямоугольник** | заданные X, Y, W, H | HUD, который никогда не двигается |
| **рядом с прошлым совпадением** | запас вокруг места, где эту же картинку видели в прошлый раз | всё, что стоит на месте; если там не нашлось — расширяется до всего экрана |
| **относительно другой картинки** | сперва найти *якорь*, потом прямоугольник рядом с ним | ряд одинаковых кнопок, где выбор решает заголовок |

Замерено на столе 2560×1440: полноэкранный шаг — около 111 мс, область в несколько сотен пикселей — около 12. Всё остальное в этом выпуске меньше этой разницы.

**по контурам** сравнивает форму, а не оттенки. На один проход медленнее, и включать это стоит тогда, когда работавший шаблон перестал находиться после смены темы или под подсветкой строки.

Как сделать шаблон — [раздел 11](#11-шаблоны-картинок-как-сделать-правильно).

### 🖱 Клик в

**Поля:** `X` · `Y` · кнопка мыши.

Кликает по точным координатам экрана. Координаты — как в записи, от левого верхнего угла (при нескольких мониторах могут быть отрицательными).

Где взять числа: в разделе **🎯 Условие по пикселю** нажмите **🎯 Взять через 3 с**, наведите курсор на нужную точку — X и Y появятся в полях, оттуда их можно переписать.

На этот шаг привязка к окну **влияет**: если окно переехало, клик поедет вместе с ним.

> 💡 Клик по фиксированным координатам — самый хрупкий вид автоматизации. Если есть возможность, используйте `Клик по картинке`.

### ⌨ Клавиша

**Поля:** клавиша из списка · `нажатие` / `отпускание`.

Отправляет **одно** событие клавиатуры. Не «нажать и отпустить», а именно одно.

Чтобы нажать пробел, нужно **два шага**:

```
0  Клавиша Space нажатие
1  Клавиша Space отпускание
```

Чтобы сделать `Ctrl+C`, нужно **четыре**:

```
0  Клавиша Ctrl нажатие
1  Клавиша C нажатие
2  Клавиша C отпускание
3  Клавиша Ctrl отпускание
```

> ⚠️ Забыли «отпускание» — клавиша останется зажатой до конца прогона. Аварийный стоп (`F9`) отпускает всё принудительно, но лучше не забывать.

Доступны 30 популярных клавиш: `Space`, `Enter`, `Tab`, `Esc`, `Backspace`, `Delete`, `Shift`, `Ctrl`, `Alt`, стрелки, `A B C D E Q R S W`, `1 2 3`, `F1 F2 F5 F8 F9`. Нужна другая — запишите её обычной записью и вставьте куском через `Воспроизвести события`.

Присвоить  круги  =   0     ← обнулить
Присвоить  круги  +=  1     ← прибавить единицу

### 🚀 Запустить

**Поля:** `Путь или ссылка` · `Аргументы`.

Открывает что угодно, не дожидаясь завершения:

| Что вписать | Что получится |
|---|---|
| `C:\Games\game.exe` | Запустит программу |
| `notepad` | Не сработает — нужен полный путь или `notepad.exe` |
| `https://example.com` | Откроет ссылку в браузере по умолчанию |
| `D:\заметки\план.txt` | Откроет файл в программе по умолчанию |
| `D:\скриншоты` | Откроет папку в Проводнике |
| `shutdown` + аргументы `/s /t 60` | Выключит ПК через 60 секунд |

Как это работает внутри: файлы `.exe`, `.bat`, `.cmd`, `.com` запускаются напрямую, всё остальное отдаётся системе через `cmd /C start` — поэтому ярлыки, документы и ссылки тоже открываются. Консольное окно при этом не мелькает.

Аргументы разделяются пробелами. Аргумент с пробелом внутри (например, путь `C:\Мои файлы\a.txt`) передать корректно не получится — это ограничение.

### 🛑 Закрыть программу

Без полей. Полностью закрывает Macro Recorder.

Нужен для сценария «отработай и выключись»:

```
...
8  Если       переменная  гемы >= 500
9      Заметка: набрали, выходим
10     Закрыть программу
11 Конец если
```

> ⚠️ Всё, что стоит **после** этого шага на верхнем уровне (не внутри `Если`/`Пока`), никогда не выполнится. Редактор подсветит такие строки оранжевым и напишет: *«⚠ Шаги ниже никогда не выполнятся»*.

### 🔤 Прочитать число

**Поля:** `Переменная` · **Обработка** · **Ожидается** · `Область` (X, Y, W, H).

Распознаёт текст в прямоугольнике экрана, вытаскивает оттуда число и кладёт в переменную.

Как задать область, не считая пиксели вручную:
1. В главном окне раскройте **🔤 Текст на экране**.
2. Нажмите **🎯 Взять через 3 с**.
3. Наведите курсор на **левый верхний** угол области, дождитесь отсчёта.
4. Наведите на **правый нижний** угол, дождитесь отсчёта.
5. Программа сразу покажет, что она там прочитала.
6. Вернитесь в шаг скрипта и нажмите **⤵ из панели** — четыре числа подставятся сами.

Что понимает распознавание чисел:

| На экране | В переменной |
|---|---|
| `1250` | `1250` |
| `Gems: 1,250` | `1250` |
| `1 250` | `1250` |
| `Осталось: 500.` | `500` |
| `02:34` | `154` (часы переводятся в **секунды**) |
| `1:02:03` | `3723` |
| `абра-кадабра` | `0` |

> ⚠️ Если OCR-движок вернул ошибку (например, область меньше 40×40 пикселей), переменная **останется со старым значением**. Учитывайте это: перед первым чтением обнулите её шагом `Присвоить`.

**Обработка** — это то, что делают с пикселями до того, как их увидит движок. Windows OCR писали для документов: тёмный текст, светлая бумага, крупный кегль — и ни одной настройки. Экранный текст не такой, поэтому всё, что можно сделать, приходится делать с пикселями заранее:

| Профиль | Что делает | Для чего |
|---|---|---|
| **без неё** | только увеличение, нужное самому движку | текст, который и так читается |
| **интерфейс** | серый, контраст растянут на весь диапазон | обычные меню и подписи |
| **мелкий текст** | то же, но увеличение сильнее | текст, в котором просто мало пикселей |
| **игровой HUD** | серый, растяжение, затем чёрно-белое по порогу Оцу | бледное число поверх движущейся картинки |
| **цифры** | чёрно-белое, сильное увеличение | счётчик на плашке |
| **перебрать** | проходит по списку и оставляет лучшее прочтение | когда неизвестно, что подойдёт |

Светлый текст на тёмной плашке автоматически переворачивается: движок учили на документах, и тёмное на светлом он читает заметно лучше.

**Ожидается** говорит, как должно выглядеть прочитанное:

| Ожидается | Проходит | Не проходит |
|---|---|---|
| **что угодно** | любое непустое прочтение | ничего |
| **целое число** | `Gems: 1,250` | `нет цифр` |
| **дробное число** | `12.5%` | прочтение без цифр |
| **время** | `02:34`, `1:02:03` | `1250` |
| **шаблон** | то, что описано шаблоном | всё остальное |

Шаблон — небольшая штука, которую можно набрать руками: `#` — цифра, `@` — буква, `?` — любой один символ, `*` — любой отрезок, в том числе пустой. `##:##` подходит к `12:34` и не подходит к `1:34`. Это намеренно не регулярное выражение.

**Прочтение, не подходящее под формат, отвергается, и переменная сохраняет старое значение.** В этом и смысл поля: неверно прочитанные часы — это не маленькая погрешность, а другое число, и тихо записать ноль хуже, чем не делать ничего.

Заодно задаётся `<имя>.quality` от 0 до 1: половина — разбирается ли формат, половина — какая доля прочитанного принадлежит алфавиту этого формата. Часы, пришедшие как `O2:3A`, проваливают первое; часы, выдернутые из предложения, — второе. При **перебрать** именно по этому числу выбирается профиль.

> 💡 В панели **🔤 Текст на экране** есть те же два списка, а рядом с прочитанным показывается оценка соответствия — так профиль можно выбирать по числам, а не на глаз.

### 🔍 Найти картинку

**Поля:** `Шаблон` · порог · `по контурам` · **в** (имя) · **Область**.

Ищет картинку и записывает, что нашёл. Никогда не нажимает — именно поэтому это тот шаг, который нужен, когда надо что-то *решить*, а не нажать.

Если в поле **в** написано `target`, заполняются:

| Переменная | Что содержит |
|---|---|
| `target.found` | 1, если оценка дотянула до порога, иначе 0 |
| `target.score` | лучшая увиденная оценка — независимо от того, прошла она или нет |
| `target.x`, `target.y` | центр лучшего совпадения |
| `target.w`, `target.h` | размер варианта, который победил |

`target.score` — самое полезное, когда шаг не срабатывает: он отличает «на экране нет ничего похожего» (0.4) от «почти, опустите порог» (0.83).

```
Найти картинку   claim → target
Если             target.found == 1
  Клик в         {target.x}, {target.y}
Конец если
```

### 🔤 Прочитать текст

То же, что **Прочитать число**, только сохраняется всё прочтение целиком, как текст. Нужен, когда на экране имя, состояние или сообщение, а не количество.

Заодно задаёт `<имя>.quality` — что это за число, написано выше, в **Прочитать число**.

| Источник | Что попадёт в переменную |

| **буфер обмена** | то, что скопировали последним, как текст |

### 📤 Записать текст

**Поля:** текст · приёмник (буфер обмена или файл с переключателем *дописывать в конец*).

`{имя}` в любом месте текста заменяется значением переменной — так скрипт ведёт собственный журнал:

```
Записать текст   "{now} прогон закончен, гемов {gems}" → C:/logs/farm.txt  (дописывать)
```

`{{` — это сама фигурная скобка. Имя, которого никто не задавал, остаётся как написано, а не исчезает: сообщение, тихо потерявшее слово, диагностировать гораздо труднее, чем то, в котором видно `{опечатка}`.

### 🪟 Найти элемент

**Поля:** `Имя` · `Тип` · `Id` · *в активном окне* · `в` · таймаут.

Спрашивает у **Windows**, что на экране, вместо того чтобы разглядывать пиксели. Там, где это работает, оно лучше всего остального: ни порога, ни разрешения, ни темы, ни языка.

- **Имя** — текст, который произнёс бы экранный диктор. Сначала точное совпадение без учёта регистра, потом вхождение подстроки.
- **Тип** сужает поиск до `Button`, `Edit`, `Text`, `CheckBox`, `ComboBox`, `List`, `ListItem`, `MenuItem`, `Tab`, `Window`. Заполнять стоит: он превращает целое окно в горстку элементов.
- **Id** — идентификатор, который приложение даёт элементу. Самое надёжное поле, когда приложение вообще его задаёт.
- **таймаут** — сколько продолжать искать. Интерфейс, который ещё дорисовывается, — обычное дело сразу после клика.

Если в поле `в` написано `elem`, заполняются `elem` (значение элемента или его подпись, если значения нет), `elem.found`, `elem.name`, `elem.x`, `elem.y`, `elem.w`, `elem.h`.

> ⚠️ **В игре он не найдёт ничего.** Unity, DirectX, OpenGL и интерфейсы на canvas рисуют себя сами и ничего не сообщают Windows. Это возможность автоматизировать обычные программы. Правильная схема — каскад: элемент → картинка → текст → координаты.

### 🖲 Нажать элемент

**Поля:** тот же запрос · кнопка мыши · *через приложение* · таймаут.

Находит элемент и нажимает его.

При включённом **через приложение** нажатие выполняет само приложение: ничего не двигается по экрану, курсор остаётся на месте, окну даже не обязательно быть активным, а элемент, сместившийся с момента поиска, всё равно будет нажат тот самый. Если нажимать у элемента нечего, шаг откатывается к обычному клику по его центру.

## 8. Условия: как макрос смотрит на экран

Условие — это вопрос с ответом «да» или «нет». Условия используются в трёх шагах: `Ждать`, `Если` и `Пока`.

Всего их восемь.

### 1️⃣ всегда

Ответ всегда «да». Зачем нужно:

- `Пока всегда` — бесконечный цикл (выходить из него придётся через `Прервать` или `Закрыть программу`);
- `Если всегда` — временно «включить» кусок скрипта, не переписывая условие.

### 2️⃣ переменная

**Поля:** имя · сравнение (`==`, `!=`, `<`, `<=`, `>`, `>=`, `has`) · число **или текст**.

```
Пока  круги < 20
Если  гемы >= 500
Если  окно has "level"
```

Переменная, которой никогда не присваивали значение, считается равной **0**.

Если обе стороны читаются как числа — сравниваются числа, независимо от того, как они хранятся: счётчик, снятый с экрана, попадает в переменную текстом и всё равно сравнивается с `10`. Иначе сравнение текстовое, с обрезкой пробелов и без учёта регистра. `has` спрашивает о вхождении — так же снисходительно, как того требует экранный текст.

> ⚠️ `==` для дробных чисел — плохая идея. `0.1 + 0.2` в компьютере не совсем `0.3`. Используйте `>=` и `<=`.

### 3️⃣ картинка

**Поля:** `Шаблон` · порог (0.30–1.00) · **Область** · **потеряно ниже** · **стабильно N / M** · `по контурам`.

«Есть ли на экране вот эта картинка?»

- **Область** работает ровно так же, как у `Клик по картинке` выше, и это самое сильное, что можно сделать для скорости.
- Побочный эффект: заполняет служебные переменные `match_x`, `match_y`, `match_score` — по ним удобно отлаживать.
- Порог 0.85 — хорошая отправная точка. Ниже — больше ложных срабатываний, выше — картинку перестанет находить из-за сглаживания.

**потеряно ниже** — второй, более низкий порог, и его стоит понять. Оценка, скачущая около единственного порога — 0.79, 0.81, 0.79, 0.82 при пороге 0.80, — читается как *четыре* смены состояния, и `Пока`, реагирующий на каждую, будет дёргаться. Поставьте **потеряно ниже** 0.70 — и картинка появляется один раз на 0.81 и не считается потерянной, пока не упадёт ниже 0.70: одна смена состояния вместо четырёх. Ноль оставляет прежнее поведение «всё или ничего».

**стабильно N / M** требует ответа в N из последних M просмотров. `2 / 3` отличает объект (0.82, 0.84, 0.83) от мелькания (0.83, 0.51, 0.74). Оба нуля — каждый просмотр решает сам за себя.

И то и другое хранится по шаблону, а не по шагу, поэтому два шага, следящие за одной картинкой, всегда согласны между собой.

### 4️⃣ пиксель

**Поля:** `X` · `Y` · цвет · `Допуск` (0–255).

«Точка (X, Y) сейчас вот такого цвета?»

Допуск — это ±N по каждому из каналов R, G, B. `20` — разумно, `0` — только строго идентичный цвет, `60` — «что-то в этом роде».

Самое быстрое из всех условий: одна точка вместо сканирования экрана. Если нужно проверять что-то в цикле сотни раз — берите пиксель, а не картинку.

Где взять координаты и цвет: **🎯 Условие по пикселю → 🎯 Взять через 3 с**.

### 5️⃣ окно

**Поле:** заголовок.

«Открыто ли сейчас окно с таким заголовком?»

Сначала ищется окно с **точно таким** заголовком. Если не нашлось — перебираются все видимые окна, и берётся первое, в заголовке которого **встречается** то, что вы ввели (регистр не важен, учитываются первые 24 символа).

То есть достаточно написать `roblox`, чтобы поймать `Roblox Player`.

Полезно для: «дождись, пока игра запустится», «если вылезло окно ошибки — закрой его».

### 6️⃣ текст

**Поля:** `Содержит` · `Область` (X, Y, W, H).

«Встречается ли в этом прямоугольнике экрана такое слово?»

Сравнение **нестрогое** и это сделано специально: регистр игнорируется, лишние пробелы схлопываются, знаки препинания выбрасываются. Потому что распознавание текста никогда не выдаёт ровно то, что видит человек.

То есть `Вы победили!` совпадёт с распознанным `ВЫ  ПОБЕДИЛИ !`.

> ⚠️ Самое медленное условие. Не ставьте его в цикл, который крутится сотни раз в секунду.
>
> ⚠️ Работает через распознавание текста, встроенное в Windows. Если игра не на английском — добавьте язык в *Параметры Windows → Время и язык*. Стилизованные игровые шрифты распознаются плохо: проверьте заранее кнопкой **🔤 Прочитать**.

У него тоже есть список **Обработка**, а искомое слово заодно служит форматом, по которому **перебрать** оценивает свои попытки.

### 7️⃣ процесс запущен

**Поле:** имя.

«Запущена ли программа с таким именем?»

Сравнение по части имени, без учёта регистра: `roblox` найдёт `RobloxPlayerBeta.exe`. Дешевле условия по окну и отвечает даже тогда, когда у программы ещё нет окна.

### 8️⃣ элемент на экране

**Поля:** тот же запрос, что у **Найти элемент** выше.

«Знает ли Windows о таком элементе интерфейса?»

Один просмотр, а не ожидание: `Ждать` и так является циклом. Молчит во всём, что рисует интерфейс само, — см. предупреждение к **Найти элемент**.

## 9. Переменные: память скрипта

Переменная — это подписанная коробочка, в которой лежит **одно значение**.

- Имя придумываете вы: `круги`, `гемы`, `n`, `count`. Русские буквы можно.
- Значение — число (можно дробное) **или текст**. С 1.4.0 текст класть можно: именно ради этого распознанная строка, заголовок окна и буфер обмена вообще появились в скриптах.
- Не заданная переменная равна **0**.

### Как ей пользоваться

Кладём значение — шаг **Присвоить**:

| Операция | Что делает | Пример |
|---|---|---|
| `=` | Записать | `круги = 0` |
| `+=` | Прибавить | `круги += 1` |
| `-=` | Вычесть | `жизни -= 1` |
| `*=` | Умножить | `ставка *= 2` |

Значение бывает **числом** или **текстом** — в шаге `Присвоить` есть переключатель. Прибавление текста к тексту склеивает их: так сообщение собирается по кускам. Два числа, которые просто хранятся текстом, остаются двумя числами и складываются.

```
Присвоить  msg  =   "прогон "
Присвоить  msg  +=  {круги}
Присвоить  msg  +=  " завершён"
```

`{имя}` в тексте любого шага — `Заметка`, `Запустить`, `Записать текст` и текстовое значение в `Присвоить` — заменяется значением переменной. `{{` — сама фигурная скобка, а имя, которого никто не задавал, остаётся как написано, а не исчезает.

Проверяем значение — условие **переменная**:

```
Пока  круги < 20
Если  гемы >= 500
Если  окно has "level"
```

### Классический счётчик

Три шага, которые надо просто запомнить:

```
0  Присвоить  круги = 0          ← перед циклом обнулили
1  Пока  круги < 20              ← условие выхода
2      Воспроизвести события 0…46
3      Присвоить  круги += 1     ← ⚠️ ОБЯЗАТЕЛЬНО внутри цикла
4  Конец пока
```

> ⚠️ Забудете шаг 3 — получите вечный цикл: `круги` навсегда останется нулём.

### Встроенные переменные

Заполняются сами, когда скрипт что-то ищет:

| Переменная | Что в ней |
|---|---|
| `match_x` | X центра последней найденной картинки |
| `match_y` | Y центра последней найденной картинки |
| `match_score` | Насколько хорошо совпало: 0.00 … 1.00 |

Шаги, у которых есть собственный префикс, заполняют больше. `Найти картинку → target` даёт `target.found`, `target.score`, `target.x`, `target.y`, `target.w`, `target.h`; `Найти элемент → elem` — сам `elem` плюс `elem.found`, `elem.name` и те же четыре числа; `Прочитать число → gold` и `Прочитать текст → line` добавляют `gold.quality` и `line.quality`.

Точка в имени ничего особенного не значит: имена переменных — обычные строки, и `target.x` — это просто переменная с именем `target.x`.

Самое полезное применение — отладка. Не находится картинка? Поставьте после проверки:

```
Если  переменная  match_score < 0.85
    Заметка: картинка не найдена, лучшее совпадение слишком слабое
Конец если
```

и посмотрите в лог.

### Стартовые значения

В интерфейсе задать стартовые значения переменных **нельзя** — при каждом запуске скрипта они берутся из поля `vars` в файле макроса, а всё остальное начинается с нуля.

Если очень нужно — откройте `.json` в Блокноте и допишите:

```json
"vars": { "круги": 0, "гемы": 0 }
```

На практике проще поставить первым шагом `Присвоить круги = 0`. Результат тот же, а руками ничего править не надо.

> ⚠️ Значения переменных **не сохраняются между запусками**. Каждый новый запуск (и каждый круг при циклическом воспроизведении) начинает всё заново.

## 10. Блоки: «Если» и «Пока»

Оба блока работают одинаково: есть открывающий шаг, есть закрывающий, между ними — содержимое. Как скобки.

### Если … Иначе … Конец если

```
0  Если  картинка: окно_ошибки ≥ 0.85
1      Клик по картинке: кнопка_ок ≥ 0.85
2      Пауза 500 ms
3  Иначе
4      Воспроизвести события 0…46
5  Конец если
6  Пауза 1000 ms
```

Читается так: если на экране окно ошибки — выполнить шаги 1–2; иначе — шаг 4. В обоих случаях дальше идёт шаг 6.

**`Иначе` не обязателен.** Часто нужен просто «сделай, если условие верно»:

```
0  Если  переменная  жизни <= 0
1      Заметка: умерли, выходим
2      Закрыть программу
3  Конец если
```

### Пока … Конец пока

```
0  Присвоить  круги = 0
1  Пока  переменная  круги < 20
2      Воспроизвести события 0…46
3      Присвоить  круги += 1
4  Конец пока
```

Как это работает:
1. Дошли до `Пока` — проверили условие.
2. Верно → выполняем содержимое, доходим до `Конец пока` и **возвращаемся к шагу 1** (проверять заново).
3. Неверно → перепрыгиваем сразу за `Конец пока`.

Если условие неверно с самого начала, содержимое не выполнится **ни разу**.

### Прервать

Досрочный выход из **ближайшего** окружающего цикла:

```
0  Пока  всегда
1      Воспроизвести события 0…46
2      Если  картинка: инвентарь_полон ≥ 0.85
3          Прервать          ← выходим из «Пока»
4      Конец если
5      Пауза 2000 ms
6  Конец пока
7  Заметка: инвентарь заполнился
```

### Вложенность

Блоки можно вкладывать друг в друга сколько угодно. Отступы в списке рисуются автоматически — по ним видно структуру:

```
0  Пока  переменная  круги < 10
1      Если  картинка: бонус ≥ 0.85
2          Клик по картинке: бонус ≥ 0.85
3          Пауза 300 ms
4      Конец если
5      Воспроизвести события 0…46
6      Присвоить  круги += 1
7  Конец пока
```

### Правила, которые проверяются до запуска

Программа не даст запустить кривой скрипт. Перед стартом она проверяет:

| Ошибка | Сообщение |
|---|---|
| `Если` без `Конец если` | `⚠ Незакрытые блоки: #0` |
| `Конец пока` без `Пока` | `⚠ Незакрытые блоки: End while #4` |
| `Пока`, закрытый через `Конец если` | `⚠ Незакрытые блоки: While #2` |
| Два `Иначе` у одного `Если` | `⚠ Незакрытые блоки: Else #5` |
| `Иначе` вне какого-либо `Если` | `⚠ Незакрытые блоки: Else #3` |

Пока горит это сообщение — **скрипт не выполняется вообще**. Не «частично», а вообще. Исправьте блоки.

### Защита от вечного цикла

Если скрипт сделает 50 000 000 шагов за один прогон, движок остановит его сам и напишет в лог `script exceeded its step budget`. Это страховка от опечатки вроде `Пока круги < 20` без `круги += 1` — не оставит систему висеть навсегда.

## 11. Шаблоны картинок: как сделать правильно

Шаблон — это маленький PNG с той кнопкой или иконкой, которую надо найти.

### Пошагово

1. Откройте игру так, как она будет выглядеть во время работы макроса.
2. Нажмите `Win+Shift+S` (встроенный «Ножницы» Windows) и выделите **только нужную кнопку**.
3. В Macro Recorder раскройте **🔎 Поиск по картинке** и нажмите **📋 Вставить**.
4. Нажмите **🔍 Найти на экране**. Должно появиться `Найдено в (x, y) — 0.98`.
5. Нажмите **💾 Сохранить PNG…** и сохраните в папку `templates/` с понятным именем, например `claim_button.png`.
6. В шаге скрипта впишите в поле `Шаблон` имя: `claim_button`.

Папка `templates/` лежит там же, где `config.json` — точный путь показан в главном окне в разделе **📁 Файлы**.

### Что делает хороший шаблон хорошим

| ✅ Делайте так | ❌ Не делайте так |
|---|---|
| Вырезайте только саму кнопку | Не захватывайте половину экрана |
| Берите то, что не меняется | Не берите таймеры, счётчики, анимацию |
| Оставляйте 30–150 пикселей по стороне | Не берите 10×10 — совпадёт с чем угодно |
| Вырезайте при том же разрешении, при котором будет работать макрос | Не переносите шаблоны с другого монитора |
| Проверяйте кнопкой **🔍 Найти на экране** | Не надейтесь, что «должно сработать» |

### Порог совпадения

| Значение | Когда |
|---|---|
| `1.00` | Только идеально совпадающие пиксели. На практике почти не срабатывает |
| `0.90` | Строго. Для чёткой статичной графики |
| **`0.85`** | **Значение по умолчанию, начинайте с него** |
| `0.75` | Мягко. Если кнопка чуть подсвечивается или пульсирует |
| `0.60` | Очень мягко. Будут ложные срабатывания |

Оценка **нормализована** — это значит, что общая яркость и контраст не важны. Шаблон, вырезанный при дневной теме игры, обычно находится и при ночной.

### Хитрость с прозрачностью

Полностью прозрачные пиксели PNG **не участвуют в сравнении**.

Значит, можно в любом редакторе (Paint.NET, GIMP, Photoshop) стереть фон вокруг круглой иконки в прозрачность — и она будет находиться на любом фоне: на траве, на камне, на воде.

### Один объект — несколько картинок

**Папка** внутри `templates/` — это набор. Положите `normal.png`, `hover.png` и `dark.png` в `templates/Claim/`, напишите в шаге `Claim` — и все три будут сравниваться с одним и тем же снимком экрана; побеждает лучшая, а `target.w`/`target.h` докладывают размер того варианта, который действительно совпал.

Экран снимается один раз на весь набор, так что лишняя цена — только сравнения. Но она линейна по числу вариантов, и именно поэтому папке нужна **область поиска**, а не весь стол.

Файлы перебираются по алфавиту, так что победитель при равных оценках не зависит от файловой системы.

### Масштаб, при котором шаблон вырезали

Картинка, снятая на экране со 150 %, в полтора раза больше той же кнопки на экране со 100 %, и никакой порог этого не перекроет.

Когда вы нажимаете **💾 Сохранить** в панели картинок, рядом с PNG пишется небольшой файл `Имя.png.json` с масштабом экрана на этот момент. При загрузке шаблон пересчитывается под тот экран, на котором его собираются искать.

У шаблонов, сделанных до 1.4.0, такого файла нет, и за них ничего не додумывается — они используются ровно такими, какие есть.

### Важно про скрипт

**«Пробовать другие масштабы»** в панели относится **только к кнопке проверки**: внутри скрипта поиск всегда идёт в масштабе 1:1, а ответом на другой экран служит пересчёт, описанный выше.

**Область поиска** больше не относится только к панели — она есть у каждого шага и каждого условия с картинкой, и задать её — самое сильное, что можно сделать для скорости. Если поиск в скрипте тормозит, сначала скажите ему, куда смотреть, и только потом уменьшайте шаблон.

## 12. Три готовых примера

### Пример A. «Кликай кнопку, как только она появится»

Задача: кнопка «Забрать» появляется когда попало. Надо жать её сразу и делать это вечно.

Понадобится: шаблон `claim.png` в папке `templates/`.

```
0  Ждать  картинка: claim ≥ 0.85  появится  (30000 мс)
1  Если   картинка: claim ≥ 0.85
2      Клик по картинке: claim ≥ 0.85
3      Пауза 500 ms
4  Иначе
5      Заметка: за 30 секунд кнопка не появилась
6  Конец если
```

В главном окне включите **Циклическое воспроизведение**. Скрипт будет крутиться по кругу: ждёт → жмёт → ждёт → жмёт.

Зачем `Если` после `Ждать`: если таймаут вышел, `Ждать` молча пропускает, и без проверки шаг 2 попробовал бы кликнуть в никуда. Впрочем, `Клик по картинке` тоже ничего не сделает, если не найдёт — но с `Заметкой` вы хотя бы увидите проблему в логе.

---

### Пример B. «Сделай ровно 20 кругов и закройся»

Задача: проиграть записанный фарм 20 раз и выйти. С паузой между кругами.

```
0  Присвоить  круги = 0
1  Пока  переменная  круги < 20
2      Воспроизвести события 0…240  (241/241)
3      Присвоить  круги += 1
4      Заметка: круг завершён
5      Пауза 2000 ms
6  Конец пока
7  Заметка: 20 кругов готово
8  Закрыть программу
```

> 💡 То же самое можно сделать вообще без скрипта: выключить «Циклическое воспроизведение» и поставить «Проигрываний: 20». Скрипт нужен, если между кругами надо ещё что-то проверять.

---

### Пример C. «Фарми, пока не наберётся 500 гемов, потом выключи ПК»

Самый жизненный сценарий. Понадобится: шаблон `claim.png` и область экрана со счётчиком гемов.

```
0   Присвоить  гемы = 0
1   Пока  переменная  гемы < 500
2       Если  картинка: окно_ошибки ≥ 0.85
3           Клик по картинке: кнопка_ок ≥ 0.85
4           Пауза 1000 ms
5       Конец если
6       Воспроизвести события 0…240
7       Ждать  картинка: claim ≥ 0.85  появится  (15000 мс)
8       Клик по картинке: claim ≥ 0.85
9       Пауза 800 ms
10      Прочитать число (1620,40 300x80) → гемы
11      Заметка: очередной круг закончен
12  Конец пока
13  Заметка: набрали 500 гемов
14  Запустить  shutdown   /s /t 60
15  Закрыть программу
```

Разбор по шагам:

- **0** — обнуляем счётчик, иначе он унаследует прошлое значение (а перед первым `Прочитать число` он и вовсе неизвестен).
- **2–5** — «санитар»: если вылезло окно ошибки, закрываем его и продолжаем. Если не вылезло — блок просто пропускается.
- **6** — основная работа: проигрываем записанный кусок.
- **7–8** — ждём кнопку и жмём её.
- **10** — читаем счётчик гемов с экрана в переменную. Область берётся из панели **🔤 Текст на экране** кнопкой **⤵ из панели**.
- **14** — команда Windows на выключение через 60 секунд. Отменить можно, набрав в терминале `shutdown /a`.
- **15** — закрываем сам Macro Recorder.

> ⚠️ Обратите внимание: выключение сделано шагом `Запустить`, а **не** через настройку «Действие после лимита» в главном окне. В режиме скрипта та настройка не работает.

## 13. Отладка: как понять, что происходит

Скрипт работает молча. Вот пять способов заглянуть внутрь.

### Способ 1. Заметки в логе — главный инструмент

Расставьте шаги `Заметка` в ключевых местах:

```
0  Заметка: === старт круга ===
1  Если  картинка: бонус ≥ 0.85
2      Заметка: бонус найден
3      Клик по картинке: бонус ≥ 0.85
4  Иначе
5      Заметка: бонуса нет, пропускаем
6  Конец если
```

Потом откройте файл лога:

```
<папка данных>/logs/macro-recorder.log.2026-08-16
```

Точный путь к папке данных показан в главном окне в разделе **📁 Файлы**. Открывается любым Блокнотом.

В логе будут ваши заметки, а рядом — служебные записи движка:

| Строка в логе | Что означает |
|---|---|
| `script: ваш текст` | Ваша `Заметка` |
| `playing events 0..=240 of 241` | Начал шаг `Воспроизвести события` |
| `wait timed out` | `Ждать` не дождался и пошёл дальше |
| `while at #3: condition false, leaving the loop` | Цикл завершился |
| `ocr read 'Gems: 1,250' [Ui q0.95] -> гемы = 1250` | `Прочитать число` сработало: что прочитано, каким профилем и насколько это похоже на нужный формат |
| `ocr read '…' does not fit Integer - гемы kept` | Прочтение оказалось не той формы, переменную не тронули |
| `element 'Save' at 812,540 (74x28)` | `Найти элемент` что-то нашёл |
| `template 'Claim' rescaled 90x30 -> 135x45` | Файл-спутник сообщил, что шаблон вырезали при другом масштабе экрана |
| `template 'claim' could not be loaded` | Файл шаблона не найден — проверьте имя и папку `templates/` |
| `ocr failed: …` | Распознавание не смогло; переменная не изменилась |
| `script rejected: unbalanced blocks near …` | Блоки не сходятся, скрипт не выполнялся |
| `script exceeded its step budget` | Сработала защита от вечного цикла |

### Способ 2. Выключайте шаги, а не удаляйте

Галочка **вкл** временно отключает шаг. Строка становится ~~зачёркнутой~~, движок её пропускает.

Так удобно искать проблему методом половинного деления: выключили половину скрипта — работает? Значит, дело во второй половине.

### Способ 3. Клавиша «Пропустить шаг»

По умолчанию она **не назначена**. Назначьте её в разделе **⌨ Горячие клавиши → Пропустить шаг:** (например, на `F10`).

Теперь во время прогона нажатие этой клавиши бросает текущий шаг и переходит к следующему. Незаменимо, когда скрипт завис на `Ждать` и вы хотите проверить, что будет дальше.

### Способ 4. Смотрите, куда он смотрит

Включите **«Показывать, куда смотрит скрипт»** в разделе **🔎 Поиск по картинке**. Поверх всего появится прозрачное окно — кликнуть по нему нельзя, а рисует оно, пока идёт скрипт:

- синий прямоугольник — где искали;
- зелёный или красный прямоугольник с числом — что нашли и насколько уверенно (зелёный означает, что обычный порог был бы пройден);
- янтарный прямоугольник — откуда читался текст;
- фиолетовый прямоугольник — найденный элемент интерфейса.

Это отвечает на вопрос, на который оценка ответить не может. Неудачный поиск выдаёт `0.41`, а `0.41` не говорит, смотрели ли не туда, не в том масштабе или на нужное место, закрытое подсказкой. Прямоугольник говорит сразу.

Это средство диагностики, а не то, что стоит держать включённым, — закончили, выключите.

### Способ 5. Проверяйте условия по отдельности

Прежде чем ставить условие в скрипт, проверьте его вручную в главном окне:

- **картинка** → **🔎 Поиск по картинке → 🔍 Найти на экране**;
- **текст** и **Прочитать число** → **🔤 Текст на экране → 🔤 Прочитать**;
- **пиксель** → **🎯 Условие по пикселю → 🎯 Взять через 3 с**.

Если условие не работает в панели, в скрипте оно тем более не заработает.

## 14. Частые грабли

| Симптом | Причина | Что делать |
|---|---|---|
| Скрипт вообще не запускается, вверху оранжевая надпись | Незакрытые блоки | Досчитайте: каждому `Если` — свой `Конец если`, каждому `Пока` — свой `Конец пока` |
| Скрипт мгновенно заканчивается, ничего не сделав | Все шаги выключены, или в начале стоит `Закрыть программу` | Проверьте галочки **вкл** и порядок шагов |
| Картинка не находится никогда | Шаблон не в `templates/`, опечатка в имени, или другое разрешение экрана | Проверьте кнопкой **🔍 Найти на экране**. В логе ищите `template … could not be loaded` |
| Картинка находится не та | Порог слишком низкий, шаблон слишком мелкий | Поднимите порог до 0.90, возьмите шаблон покрупнее и характернее |
| `Ждать` не ждёт, летит дальше | Условие уже верно, или вышел таймаут | Увеличьте таймаут; проверьте `появится` / `исчезнет` |
| Цикл `Пока` крутится вечно | Внутри нет шага, который меняет переменную | Добавьте `Присвоить круги += 1` **внутрь** цикла |
| Клавиша осталась зажатой | Есть `нажатие` без `отпускания` | Добавьте парный шаг. `F9` отпускает всё принудительно |
| Клики попадают мимо | Окно переехало или изменило разрешение | Используйте `Клик по картинке` вместо `Клик в`, либо включите привязку к окну |
| `Прочитать число` даёт 0 | OCR ничего не распознал | Проверьте кнопкой **🔤 Прочитать**. Возьмите область побольше, добавьте язык в Windows |
| `Прочитать число` не меняет переменную | Ошибка OCR (например, область меньше 40×40) | Увеличьте область. В логе будет `ocr failed` |
| Ползунок скорости ни на что не влияет | В скрипте он действует только на `Воспроизвести события` | Правьте значения в шагах `Пауза` |
| Стоп по пикселю не срабатывает | В режиме скрипта настройка **🎯 Условие по пикселю** не работает | Используйте условие `пиксель` внутри `Ждать` / `Если` / `Пока` |
| ПК не выключается после лимита времени | В режиме скрипта «Действие после лимита» не работает | Шаг `Запустить` → `shutdown` с аргументами `/s /t 60` |
| Скрипт стоит на месте, в статусе «Жду окно…» | Включено **Целевое окно → Пауза, пока оно не впереди** | Переключитесь на нужное окно или снимите галочку |
| Всё замерло, статус «Удержание» | Приложение на другом виртуальном рабочем столе | Вернитесь на тот стол, где открыт Macro Recorder |
| Экспортированный `.exe` не находит картинки | Шаблоны не приложены | Скопируйте папку `templates/` рядом с экспортированным `.exe` |
| Экспорт в `.ahk` потерял всю логику | Так и задумано | В AutoHotkey переносятся только записанные события |

## 15. Чего скрипт не умеет

Честный список, чтобы вы не искали несуществующие кнопки:

- **Нет текстовых переменных.** Только числа. Строку сохранить некуда.
- **Нет арифметики между переменными.** Можно `круги += 1`, но нельзя `итог = круги * гемы`. Только переменная и константа.
- **Нет функций и подпрограмм.** Повторяющийся кусок придётся продублировать.
- **Нет `и` / `или` в условиях.** Одно условие = одна проверка. Комбинация делается вложенными `Если`:
  ```
  Если  картинка: A ≥ 0.85
      Если  переменная  гемы > 100
          ...
      Конец если
  Конец если
  ```
- **Нет `иначе если`.** Делается вложением `Если` внутрь `Иначе`.
- **Нет ожидания завершения программы.** `Запустить` стартует процесс и сразу идёт дальше.
- **Нет чтения файлов, буфера обмена и сети.**
- **Нет доступа к `match_x` / `match_y` в шаге `Клик в`.** Поля там — обычные числа, подставить туда переменную нельзя. Для клика по найденной картинке есть отдельный шаг `Клик по картинке`.
- **Переменные не переживают перезапуск.** Каждый запуск начинается заново.

Если упёрлись в этот список — вам, скорее всего, нужен AutoHotkey. Это нормально: Macro Recorder задуман как рекордер с условиями, а не как язык программирования.

## 16. Как это выглядит внутри файла

Скрипт хранится прямо в файле макроса (`.json`). Открывается любым текстовым редактором — правьте, если удобнее так.

```json
{
  "version": 3,
  "duration_us": 8000000,
  "events": [ ... ваша запись ... ],
  "script": [
    { "kind": { "SetVar": { "name": "круги", "op": "Set", "value": 0.0 } }, "enabled": true },
    { "kind": { "While":  { "cond": { "Var": { "name": "круги", "cmp": "Lt", "value": 20.0 } } } }, "enabled": true },
    { "kind": { "PlayEvents": { "from": 0, "to": 240 } }, "enabled": true },
    { "kind": { "SetVar": { "name": "круги", "op": "Add", "value": 1.0 } }, "enabled": true },
    { "kind": "EndWhile", "enabled": true }
  ],
  "vars": { "круги": 0.0 }
}
```

Соответствие названий:

| В интерфейсе | В файле |
|---|---|
| Воспроизвести события | `PlayEvents { from, to }` |
| Пауза | `Wait { ms }` |
| Ждать | `WaitFor { cond, appear, timeout_ms }` |
| Клик по картинке | `ClickImage { template, threshold, button }` |
| Клик в | `Click { x, y, button }` |
| Клавиша | `Key { vk, down }` |
| Присвоить | `SetVar { name, op, value }` |
| Если / Иначе / Конец если | `If { cond }` / `Else` / `EndIf` |
| Пока / Конец пока / Прервать | `While { cond }` / `EndWhile` / `Break` |
| Запустить | `Run { path, args }` |
| Закрыть программу | `Exit` |
| Заметка | `Log { text }` |
| Прочитать число | `ReadNumber { x, y, w, h, var }` |

Условия: `Always`, `Var { name, cmp, value }`, `Image { template, threshold }`, `Pixel { x, y, r, g, b, tol }`, `Window { title }`, `Text { x, y, w, h, needle }`.

Сравнения: `Eq` `Ne` `Lt` `Le` `Gt` `Ge`. Операции: `Set` `Add` `Sub` `Mul`.

> ⚠️ Если сохранить файл с ошибкой в JSON, программа откажется его открыть. Сделайте копию перед правкой.
>
> ⚠️ Файл с расширением `.mrz` — сжатый, Блокнотом не откроется. Пересохраните как `.json`.

## 17. Шпаргалка на одну страницу

**Открыть редактор скрипта:** главное окно → **✂ Редактор** → **✂ Открыть редактор** → вкладка **Скрипт**

**Добавить шаг:** выбрать вид в списке → **Добавить** (вставится после выделенного)

**Аварийный стоп:** `F9`

---

**Шаги**

```
Воспроизвести события с…по   проиграть кусок записи
Пауза N мс                    просто подождать
Ждать <условие> появится/исчезнет (таймаут)
Клик по картинке <шаблон> <порог> <кнопка>
Клик в X,Y <кнопка>
Клавиша <клавиша> нажатие/отпускание
Присвоить <имя> = += -= *= <число>
Если <условие> … Иначе … Конец если
Пока <условие> … Прервать … Конец пока
Запустить <путь> <аргументы>
Закрыть программу
Заметка <текст>
Прочитать число <область> → <переменная>
```

**Условия**

```
всегда
переменная <имя> == != < <= > >= <число>
картинка <шаблон> <порог 0.30–1.00>
пиксель X,Y <цвет> <допуск 0–255>
окно <заголовок>
текст «слово» <область>
```

**Три вещи, о которых забывают чаще всего**

1. Каждому `Если` — свой `Конец если`. Каждому `Пока` — свой `Конец пока`.
2. Внутри `Пока` обязан быть шаг, который меняет переменную из условия.
3. Каждому `Клавиша … нажатие` — свой `Клавиша … отпускание`.

**Порог совпадения:** начинайте с `0.85`, не находит — `0.75`, находит лишнее — `0.90`.

**Лог:** `<папка данных>/logs/macro-recorder.log.ГГГГ-ММ-ДД` — путь к папке показан в разделе **📁 Файлы**.
